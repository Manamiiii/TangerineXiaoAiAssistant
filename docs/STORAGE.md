# 本机目录与迁移（0.4.2）

新装程序与默认运行数据集中在当前用户的 `%LOCALAPPDATA%\Tangerine`。身份、配置 JSON 格式和 Windows 当前用户 DPAPI 的加密方式不变。安装版、便携版、源码默认入口使用同一正式数据；只能启动一个默认实例。本轮仅用虚构数据测试，未搬迁开发机的真实数据。

## 目录地图

以下相对路径基于 `%LOCALAPPDATA%\Tangerine`。

| 目录 | 写入内容与生命周期 |
|---|---|
| `Apps/TangerineXiaoAiAssistant` | 新装 Setup 的程序、许可、对应源码及卸载程序。便携包在用户解压位置，源码从工程运行。 |
| `Data/TangerineXiaoAiAssistant/Config` | `config.json`，保存设备选择、白名单与设置。原子保存时在同目录创建短暂 `.tmp`。 |
| `Data/TangerineXiaoAiAssistant/Storage` | `xiaomi.dpapi`，加密令牌；保存时有短暂 `.tmp`。不保存明文密码。 |
| `Data/TangerineXiaoAiAssistant/Backups` | `config.json.bak`，上一次有效配置；保存时有短暂 `.tmp`。 |
| `Data/TangerineXiaoAiAssistant/Logs` | `assistant.log` 和两份轮转日志，约 1.5 MB。 |
| `Data/TangerineXiaoAiAssistant/Runtime` | 单实例与维护锁、布局与初始化标记；测试身份的协作退出标记也在此。 |
| `Data/TangerineXiaoAiAssistant/Temp` | CLI 扫码的 `login-qr.png`，正常结束删除；桌面二维码只在内存。异常退出可能遗留，退出助手后可手动删除。 |

只按实际用途建立子目录，没有业务数据库、Cache 或内嵌浏览器 profile。升级、卸载不清理这些数据，也不递归删除 `Tangerine`、`Apps`、`Data` 或兄弟应用。

## 旧安装与旧默认数据

程序目录以同一卸载登记和 GUID 标记确认归属。已安装在 `%LOCALAPPDATA%\Programs\TangerineXiaoAiAssistant` 或 `%LOCALAPPDATA%\Programs\Tangerine\TangerineXiaoAiAssistant` 的实例继续原位升级。未安装时才采用新的 Apps 位置。多处标记同一身份、登记异常或目录重解析时拒绝维护，不移动程序或改接既有自启入口。

唯一受支持的历史默认数据来源是 `%LOCALAPPDATA%\TangerineXiaoAiAssistant`，所有 0.4.1 及更早版本均使用这个平铺目录。不会搜索用户其他目录或猜测多份数据的优先级。

新版本首次默认启动先取得新旧互斥锁，核对两边内容，验证已有配置与备份。只有旧布局已知文件且目标没有业务数据时才迁移。冲突、未知文件、损坏配置、链接路径或占用会停止启动。已有新旧两份配置时不会按时间选择，也不会合并。

迁移先在旧根写入 `tangerine-migration.json`，记录布局、应用身份和原始文件散列。逐文件复制到新分类目录并校验字节；凭据直接复制加密字节，迁移代码不解密、不重存明文。原件保留在旧根的 `tangerine-originals`。旧 `config.json` 原子替换为旧程序无法接受的提示配置，最后写入新 Runtime 的完成标记。原始配置始终有完整副本，不经过缺失配置的窗口。

旧默认根继续保留两个兼容锁、迁移记录、提示配置和只读意义上的原件存档，这是兼容例外。不要删除它们或将存档当作当前配置修改。当前运行配置只在新 Data 下写入。每次启动复核记录和原件；旧位置重新出现凭据或被改回旧配置会停止新版，防止悄悄形成两套数据。旧版默认入口会因提示配置拒绝启动；不要删掉提示配置强行启动旧版。

新程序同时持有旧版本能识别的锁。旧程序正在工作时不能迁移，新程序运行时旧程序和旧安装器也不能操作同一正式实例。安装器降级检查保持启用。显式指定的独立目录仍由用户管理，不能与正式实例自动同步。

## 中断、恢复与回退

迁移不自动续跑或回滚。若复制失败、空间不足、断电或完成标记缺失，下一次启动会提示迁移未完成；部分目标文件不会当作已成功迁移的数据运行。

1. 正常退出所有版本，保留新 Data 和旧默认根的完整副本。不要删除 journal、锁或标记来跳过检查。
2. 对照 journal 中的相对文件名和 SHA-256 检查原件。中断时原件可能尚在旧根，也可能已在 `tangerine-originals`，两处都需要保留。不要把凭据或完整目录发送到 Issue。
3. 需要应急恢复时，由维护者确认一组一致的配置与加密凭据，复制到另一个用户明确选择的独立目录，使用当前版本的 `--data-dir` 指向该目录。该目录使用平铺格式，并保留所有原件；凭据只能由原 Windows 用户使用。先做规则演练，再决定恢复默认目录。不要自动取“较新”文件拼接两份状态。
4. 已完成迁移后如需回退，先保全新版后续更改。旧根存档只代表迁移时状态。Setup 拒绝降级；不得将旧便携程序指向新分类目录。确需历史版本调查时仅使用独立副本与显式数据参数，不恢复旧默认入口或并行监听。

配置日常恢复在完全退出后，把 `Backups/config.json.bak` 复制回 `Config/config.json`。保留损坏文件供本机排查；配置缺失或损坏时不会自动重建已有初始化数据。恢复格式不变。

## 显式参数与系统例外

- `--data-dir` 优先，继续采用原平铺格式，适合独立测试/外部目录；明确指向新默认 Data 根时采用分类格式。已退休的旧默认根有迁移记录，当前版本会拒绝将其作为外部平铺目录重新写入。
- `--config` 优先于默认 Config，配置与相邻 `.bak` 保留在用户指定位置；若指定的正是默认配置文件，备份使用 Backups。相对路径仍按调用者工作目录解析。显式外部路径不会被自动搬迁。
- 安装维护写入当前用户 HKCU 卸载登记、开始菜单和主动选择的桌面快捷方式。用户主动启用自启时才写入当前用户 Run 值；本轮不操作真实入口和自启。
- PyInstaller onefile 解包和 NSIS 自解包/卸载使用系统临时目录，由运行时管理；Windows 自身还可能保存应用兼容性、安全检查等系统记录。无需管理员权限，不承诺系统零痕迹。
- 打开的网页使用用户默认浏览器及其独立 profile，打开的外部应用管理自身数据；助手不搬迁这些文件。没有本地 HTTP 服务或端口。
- 开发依赖、打包输出与隔离测试仍在工程 `.venv`、`build`、`dist` 或系统测试临时目录；它们不属于正式运行数据。独立测试身份的目录名带 fixture UUID，禁止用测试流程清理正式实例或历史 fixture。
