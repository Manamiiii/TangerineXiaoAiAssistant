## 待真机验证（用户当前无法进行，暂缓）

必要步骤，方便时进行：

1. 打开 `dist/TangerineXiaoAiAssistant/login.cmd`，用米家 App 扫码确认；成功后选择音箱。预期显示登录成功及设备选择已保存。
2. 打开 `probe.cmd`。预期显示设备可访问、对话读取成功的记录数。返回 0 条只证明接口成功，不证明能收到之后的语音。
3. 打开 `run.cmd`，等“音箱记录已同步”，再对音箱说“小爱同学，让电脑打开 B 站”。预期打开一次 `https://www.bilibili.com`；等待 10 秒不应重复打开。
4. 按 Ctrl+C 停止，再重新运行。预期不重复执行刚才的历史语音。

可选验收：

- 从 0.1.0 升级时先停止原运行窗口，再执行新包的 `upgrade-config.cmd`，预期设备和原命令保留。
- 执行 `configure-app.cmd` 登记已安装应用，重启运行窗口后说“让电脑打开微信”，预期启动所登记的 EXE。
- 说“让电脑把音量调到三十”，预期系统音量约 30%；静音状态保持原样。
- 在可以锁屏的时候说“让电脑锁屏”，预期 Windows 显示锁屏界面。自动化开发测试没有代替这一人工验收。
- 执行 `TangerineXiaoAiAssistant.exe tts-test`，确认实际发声。接口接受请求不等于听到了播报；不支持时可设 `tts_reply: false`。
- 临时断网再恢复，确认日志退避并恢复；恢复后重新发出指令。旧指令超过 30 秒不执行是预期行为。
- 在 `run --dry-run` 下先验证音箱识别能命中规则，不打开网页、不播报。

不要将密码、Token、二维码或完整云端响应贴到 Issue。排错只需要设备型号、操作步骤和本程序的脱敏状态提示。
